# M2a — reviewed evidence + acknowledgement decisions

This directory holds the **durable, committed** evidence for reading ITG's Monday
boards (it survives the gitignored `snapshots/` purge). Raw PII dumps stay local
under `snapshots/`.

| File | Status | What |
|---|---|---|
| `acknowledgements.json` | **LIVE** | Reviewed human decisions, consumed at runtime by the engine and the readiness report. |
| `audit-report.md` | **LIVE** | Sanitized aggregate audit, regenerated by `pnpm audit:mapping`. No personal PII. |
| `recommend-parity.md` | **LIVE** | Generated by `pnpm recommend:parity`. Do not hand-edit. |
| `parity-diff-investigation.md` | **LIVE** | Hand-written conclusions about parity diffs. Never regenerated. |

---

## ⚠️ The sync flow this file used to describe is HISTORICAL

M2a originally pulled every board into Postgres in one atomic
`apply_monday_snapshot` transaction, recorded in `sync_runs` and driven by
`pnpm sync:monday`. **That is gone.** The database was removed on 2026-08-04 —
Monday is the source of truth and every read is live. See `docs/build/BRIEFING.md`
and `docs/m2b/README.md`.

Commands that no longer exist: `pnpm sync:monday`, `pnpm seed`, `pnpm db:reset`,
`pnpm db:types`, `pnpm test:integration`.

What replaced it: the engine reads the trainers board and the Thema's board live per
execution (`lib/recommend/roster.ts`, `lib/recommend/qualifications.ts`), carrying the
same completeness, coherence and column-schema gates the sync had — they now fail the
**read** instead of failing an import.

---

## What acknowledgements still do

`acknowledgements.json` is **not** historical. It is imported directly by
`lib/recommend/deps.ts` and used by both the engine and the readiness report, so the
two cannot disagree about a resolved conflict.

The bucket that still matters day to day:

- **`qualConflicts`** — a trainer×theme observed in two REAL colours, with the
  reviewed effective `green`/`red`. Bound to the exact observed colour set, so a
  stale decision cannot be silently reused after the colours change.

  `grijs` no longer participates: it is the *not assessed* bucket and is dropped
  before conflict detection (`assessedColours`). Before that fix, ITG's 30-July
  groen/rood migration produced 382 "conflicts" and silently excluded three trainers
  from ~95 themes each.

The other buckets (`noBedrijfKlant`, `klantAliases`, `acknowledgedGroups`) were
import-time concerns for the Postgres apply. They are inert now, kept for provenance
rather than consumed.

## Still-current commands

| Command | What |
|---|---|
| `pnpm snapshot:monday` | Read-only board dump to `snapshots/` (fatal completeness/coherence/version gates). |
| `pnpm snapshot:airtable` | Legacy Airtable dump — the parity baseline. Take a final one before Airtable goes read-only. |
| `pnpm audit:mapping` | Regenerates `audit-report.md` from the snapshots. |
| `pnpm recommend:parity` | Live comparison against the legacy Airtable snapshot; writes `recommend-parity.md`. |
